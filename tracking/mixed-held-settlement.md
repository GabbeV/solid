# Mixed source/render parking and the actual held scan

This extends the quiet-intake contracts to an actual held source followed by a
newly held childless reader. The runtime, source pin178605cf, checker profile and
fuel are unchanged. Nine composed roots are added to LAWS/PROOF; only the normal
completed whole-book verdict and exact input seal grant checkpoint proof credit.

## Initial facts, derived outcomes

`park-admission` certifies a finite captured pending list, with either an already
held/override unstaged entry or a supported childless reader at each actual
successor World. Its endpoint does not contain a desired result World, health or
count. `park-admitted-loop` derives completion using the runtime's own budget,
executes the actual walk and clears its intake. Every successor's health follows
from the corresponding operation contract and the initial health premise.

`park-mixed-construction` constructs that admission for `[source, reader]` from
the initial list, source flags and reader facts. The real first park is identity;
the second reader rule is transported across that equality. The result is actual
`holdNode(reader, group)` with the intake cleared. There is no substituted park
algorithm and no preallocated extension introduced into the runtime.

The reader rule supports the earlier allocated/unowned pending-value leaf, and
now a **fresh render reader with an absent pending slot**. A trace of the actual
render pass showed this branch is needed: the proposal lives in `prevValue`,
while `pending` remains empty and `x` remains zero before parking. Solid exempts
render nodes from the uninitialized memo-loading skip. The new contract follows
that branch, allocates the extension during actual `holdNode`, derives its exact
node record and proves the childless frame walk is identity. It does not assume a
pending value, an existing extension or a post-park healthy World. Initial valid
node, childless, eligibility and render/empty-slot facts remain explicit. It is
not a global well-formedness certificate for arbitrary malformed arenas.

`holding-outer` masks only node, extension and group arenas and proves every
other World field is retained by actual holding, including current source-pin
lane globals, faults, captures, queues and pending intake. `holding-committed`
separately retains every stored committed value, tree and event trace. Group
membership may change; existing count/metadata frames retain action debt.

`mixed-settle` and `mixed-settle-scan` compose this intake with the actual
settlement continuation and its next scanner step. Initial health, no comparator
bindings, ordinary terminal group, quiet lane hooks and no deferred zombies are
explicit. With a singleton live group and positive initial action debt, the two
actual steps construct their scanner, retain the group and caller tasks/stack,
and preserve committed storage/tree/trace. Post-park health, live-list, count and
quiet-hook premises are derived, not supplied again. This starts at
`SettleApplied`; it does not yet prove that the queued Round/heap reaches it.

`data-result` also proves ordinary result classification for arbitrary represented
values other than the admitted `AsyncValue` protocol carrier. This includes
opaque references, falsy values and function identities, without restricting the
data to natural numbers. It is an actual finishShape→finishReady boundary, not a
claim about arbitrary JavaScript mutable protocol objects or async completion.

## Evidence and remaining composition

The new mixed/native control compares 320 actual whole-settle cases against the
unchanged pinned source. It varies render versus memo, fresh versus allocated
extension, absent/undefined/false/zero/numeric pending slots, initial pending and
uninitialized status, staging and retained action debt. It checks exact ownership,
member order, count, state and caller continuation. These use private seeded
states, so they do not establish public reachability. Three compiled semantic
mutations are rejected: treating an unready render as a memo, omitting fresh
membership, and skipping the second intake entry. All mutation targets are current;
this is not a new complete mutation sweep.

The remaining priority is to construct the mixed certificate after actual queued
Round/heap processing, then continue to the other action's next actual delivery.
The broader global forest/live-list, once-only action/flight ledger, arbitrary
branching publication safety and eventual reveal theorem remain open. No new
upstream bug or workaround was found in this milestone.
