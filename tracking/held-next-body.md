# Derived handoff to the other controller's finite body

The actual pair constructor now supplies both finite method bodies. Either
controller can run first, independently of join direction. Its actual captured
resume/preparation and finite body build the source cache route/profile and the
other controller's captured route, positive identity and method certificate at
the actual resulting World. Its one-obligation count evidence supplies the next
resume's initial count. The other controller's actual current-group resume and
arbitrary finite setter body then retire that last obligation. Closed roots
construct the handoff and derive an actual final count of zero and restoration
of the second caller's arbitrary value stack. No intermediate World, final count,
source profile, alias/capture/method certificate or resolver answer is supplied.

The preservation arguments are reusable. Real preparation changes only the
selected controller's method; a different controller retains its full record.
Finite held setters, retirement and output handling preserve all controller
records after that preparation and every redirect pointer. Rebased aliases
retain origin, terminal, depth and arena room. Empty body lists keep the actual
old source cache; the first real setter in a nonempty list constructs a canonical
cache successor. Retirement moves the actual route and virtual profile without
rewriting the runtime cache. The successor is constructed by induction and
precise operation frames, not by assuming the desired facts after each task.

This is an internal two-resume handoff contract. The second resume starts with
the exact full World produced by the first prefix, and has its own explicit
caller task/value suffix. It does not claim one uninterrupted core/host execution
through the first prefix's queued observer/output/slice/Round continuation. Those
continuations are not executed or discarded by this theorem. A public host trace
must connect them and account for ambient question/action-depth restoration
before the next delivery. Existing finite native/Bend public pair controls are
supporting evidence for that broader behavior, not a proof of that missing path.

A zero action count also does not imply that result Promise adoption, owned
flights, queued flush or renderer publication have completed. Those remain
separate obligations. Full public factory/parking/host construction, mixed
interception, arbitrary branching flight histories and eventual reveal are open.
