# Permitted source-Set histories and constructed return

`pending-source-history.bend` admits arbitrary finite branching sequences of the
actual `addPendingSource` and `removePendingSource` helpers. Each event certificate
checks valid target and source IDs in that event's actual input World. It does
not supply a transition, output frame or invariant equation. The executor uses
the same source operations; an erased scope indexes certificates and the runtime
World advances through those actual operations.

Induction proves committed values/tree/trace, subscriber shape/all links, node
count and fault unchanged through the whole history. A constructor-supplied
one-edge certificate survives, then supplies the existing bounded settlement
return and complete content frame. The bound is ten Core tasks **after** the
history. It is not a constant-time bound for the history, Set scans or World size.
The returned World is the one computed by the actual operations/Core steps; a
fault or absent-carrier early return remains a permitted alternative.

`pending-command-history.bend` constructs all event-validity certificates from
the graph certificate for an arbitrary list of add/remove choices along the
selected source-to-leaf relation. No validity proof is supplied by JavaScript.
`memo-render-source-history.bend` composes actual default memo/render allocation,
setup and linking with that constructor and the bounded return/frame theorem.
The initial context is the same healthy reserved arenas/null-parent invariant;
no final metadata/transition/frame or history certificate is an input.

Nine roots extend 538 to 547. The typed fixture checks 131 finite histories:
every binary order through length six plus long cycles up to 64 operations,
rotating existing-node counts, payloads and caller continuations. These retain
old Set tombstones across re-registration, match a direct actual-helper replay,
and pass 393 actual-driver split comparisons. Finite final-membership checks
supplement the generalized frame/validity/return proof; final Core membership or
readiness is not a new generalized theorem. Three focused kernel mutations
reject cache, subscriber-shape and node-arena corruption during removal.
[Validation](reviews/pending-source-histories-validation.json).

These are source-Set subprotocol histories. Valid IDs alone do not prove that a
full public callback/flight controller can generate every event order. General
fresh-carrier membership is proved separately; its extension-zero/auxiliary-arena
premises have not yet been derived from the arbitrary-sized memo/render graph.
Status/readiness, full once-only action/flight accounting, arbitrary topology,
owner callbacks and coordinated flush/reveal remain open. Eventual host delivery
and fairness are not asserted.

Runtime/source/host, task budgets and kernel limits are unchanged, with all
previous domains retained and no active semantic deviation. Current mutations:
